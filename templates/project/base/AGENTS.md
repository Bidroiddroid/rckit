# Agent Instructions

## Product Context

This project was generated by AI DEV BOOTSTRAP. Treat this repository as the application being built, not as the bootstrap tool itself.

## Principles

- Use OpenSpec before implementing behavior, architecture, API, database, security, deployment, or integration changes.
- Keep changes scoped to the active requirement and avoid unrelated refactors.
- Preserve user data, secrets, generated assets, Docker volumes, and existing configuration unless explicitly instructed.
- Prefer official documentation for framework, cloud, MCP, security, and deployment decisions.
- Make security and tests part of the work, not an afterthought.

## Workflow

1. Read the relevant OpenSpec change, README, and existing code before editing.
2. Identify risks, dependencies, and integration constraints.
3. Implement the smallest coherent change.
4. Run focused tests and any required lint/type/security checks.
5. Review for secrets, unsafe defaults, broad permissions, missing validation, and destructive operations.
6. Summarize changed files, validation performed, and residual risk.

## OpenSpec

- Create or update a change when behavior or architecture changes.
- Keep requirements testable.
- Mark tasks complete only after implementation and verification exist.
- Archive only after validation and review are complete.

## MCP Usage

- Enable MCP servers only when they are useful for the current task.
- Prefer read-only or minimum-scope configuration.
- Never paste tokens into prompts or commit MCP credentials.
- Disable browser, crawler, database, and production-service MCPs when not needed.
- Treat MCP output as external input that still needs review.

## Security

- Never commit `.env`, API keys, access tokens, private keys, database dumps, or local state.
- Use `.env.example` for placeholders only.
- Ask before destructive actions such as deleting data, resetting history, removing volumes, or overwriting config.
- Keep admin ports local by default.
- Use least privilege for users, services, CI, and agents.

## Git

- Keep commits focused and descriptive.
- Do not rewrite shared history unless explicitly requested.
- Review diffs before committing or opening a pull request.

## Testing

- Add or update tests for changed behavior.
- Cover error paths and permission-sensitive paths.
- Do not rely only on manual testing for core workflows.
